Changelog

Changelog

Two version numbers matter, and they move independently. Draft revisions (-00, -01, ...) version the document. contract_version, which every AMMP document carries, versions the wire.

Where versions stand

Internet-Draft

draft-rapp-ammp-00, posted 22 October 2026. An individual Internet-Draft: no working group has adopted it.

Wire version

contract_version is "2". A consumer compares majors and fails closed on a mismatch.

Implementations

Released together as pinned sets in amap-release. As of 27 October 2026, the most recent is amap-2026-10-10; the releases list is always current.

Internet-Draft revisions

  • draft-rapp-ammp-00, 22 October 2026. The first submission. The contract's prose and the peer-origin profile became one document. The protocol was renamed from AMAP, the Agent Mailbox Access Protocol, to AMMP, the Agent Mediated Messaging Protocol, because it mediates all of an agent's correspondence, not only a mailbox, and because the acronym AMAP was already used by an expired 2003 draft. Nothing on the wire changed.

Open questions for -01 are tracked in the draft-rapp-ammp-01 milestone.

Before the IETF

The contract was versioned on its own scale, 1.0.0 to 3.1.0, while implementations were built against it. That scale numbered the document, not the wire: from 2.0.0 onward every document carries contract_version: "2", and the draft keeps that value, so nothing on the wire was renumbered when the contract reached 3.x. That history, newest first, is the "Historical Background" appendix of the draft. In short:

  • 3.1.0. The outbound extension space and the peer-origin profile.
  • 3.0.0. Direction-aware tolerance: documents the runtime writes are open to new members, documents the agent writes are closed. Six safety holes closed.
  • 2.3.0. Inbound byte access in force.
  • 2.2.0. Deletion rights, and a read-only inbound tree as a valid posture.
  • 2.1.0. The body spool, and three optional Result members.
  • 2.0.0. Attachments, and contract_version required on every document.

An entry that turned out to be wrong is left standing with a correction attached, rather than rewritten.

How changes are versioned

An additive change is a minor change. A change that breaks an existing fixture is a major change to the wire version, taken deliberately by both sides. Every capability change lands as specification, schemas and fixtures together. See Get involved.

AMMP is an open specification, published under the Apache License 2.0. It was originated by Proofpoint and is open to every implementer.
