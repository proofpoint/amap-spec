Open, so it can be checked

All four repositories are public under the Apache License 2.0:

  • amap-spec: the specification, JSON Schemas, conformance fixtures, and the Internet-Draft rendering
  • amap-router-local: the reference runtime
  • amap-connector-claude: the Claude Code connector
  • amap-deploy-sandy: a working deployment of the two on one host, with a walkthrough that gets two agents talking

Anyone can test any vendor's runtime or connector against the public fixtures, plus the operational checks the specification requires. Passing the fixtures alone isn't conformance (§ Conformance). See For implementers.

Built with itself

  1. Early AMAP carried the work of building AMAP. Agents developing the specification and the reference implementations coordinated through early versions of the protocol.
  2. The specification and its implementations matured together. The specification, the reference runtime and the Claude Code connector grew up side by side.
  3. Fleet week. Once the protocol and implementations could support it, ten sandboxed Claude agents, each owning a repository, worked together through AMAP for one week. They ran a conformance sweep, a security audit and a multi-repository release.

The fleet found defects in the specification itself, not only in code:

  • Two clauses of the submit-request section collided: reply binding versus "never transmit to an unnamed address".
  • A validator ignored its arguments and reported green for the wrong reason.
  • Mutation testing showed that only 44 of 301 schema constraints were pinned by any fixture.

This is evidence of agent-to-agent use under one operator. It is not yet evidence of adoption across organisations.

The IETF

We intend to submit the draft, ask for it to be considered at Dispatch, and, if there is interest, work toward a BoF. AMAP is not an IETF standard. See AMAP at the IETF.
